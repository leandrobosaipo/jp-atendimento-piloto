## Preparing one permit

From a private approved envelope, run `python3 issue.py NEW_PRIVATE_DIRECTORY < approved.json`. The input contains the existing contact task digest as `task`, the exact native `body`, `role=registration`, `operation=contact`, a known `operator`, explicit `approved=true`, a Unix-second expiry no more than five minutes away, and the authoritative boolean `cacheExists` from the independent cache check. The body includes the current human-app contact observation, timestamp and unique proof, the reviewed desired name and the expected cache name. A fresh signed-in person must observe the phone and name in the actual contact view. The operator must derive the approved envelope from the admitted native request and compare the two observations individually.

Transfer only the appropriate file on authenticated private channels. The Mac receives `mac/<task>.json` in a root-controlled directory mounted read-only at `/run/contact-permits`. Grant files may be root-owned 0440 with only the service group permitted to read. The Dell receives `dell/<task>.json` under `/etc/jp-task-effects/contact-permits/` with root ownership and 0600 permissions. The per-task secret is generated locally and the Mac file contains its digest. Keep intent history on a dedicated persistent volume mounted at `/var/lib/contact-intents`, restricted to the service UID. A single writer owns this ledger across process and image replacements. Neither device may issue another permit for an unresolved intent.

The adapter validates the independent observed device name and the cache baseline, the target instance, the body digest and the existing bidirectional PN/LID mapping. It persists a recipient lock and task intent before a single native call. The conditional local cache update and reread follow provider acknowledgment. The separate read route reports a nonauthoritative cache result. WhatsApp exposes no atomic compare-and-swap of the name on another device. A fresh human check after the write is required for final confirmation. An observer can change the device entry between checks. The runtime retains a recipient lock even on accepted-unverified. During a later quiesced reconciliation the authorized operator archives that lock only after reviewing the original intent and device outcome. Preserve the immutable intent and observed files. Never use a fresh approval or a different task to retry an ambiguous contact.

The private Dell rehearsal additionally exercises the genuine compiled route and forwarding methods from the pinned bundle, creates no Evolution process or WhatsApp session and never mounts production data. Alternate builds require a fresh source review.

The current running process cannot acquire the on-disk code merely by placing a file beside it. Keep the current service and credentials untouched while process reload is prohibited. Provision the dedicated private route, prior-image backup, app-state custody, scoped host reader/writer, mounted permit and intent directories before considering activation. Restoration selects the prior image and persisted session with the old broad flag disabled. Ledger and unresolved intents survive rollback.
